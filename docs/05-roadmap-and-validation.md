# 05 · 开发路线、验证计划与开放问题

## 1. 迭代路线（依验收推进，不承诺固定工期）

### Milestone A：项目基础与可用 Demo
- 确认 Web + Vue3/Spring Boot、PostgreSQL 版本；CI/本地 Compose。
- 建立 5–10 篇权利明确或自写的英文教学短文（B1 为主），每篇附参考来源 URL 与权利说明。
- 实现文章列表、阅读器、AI 流式讨论、结束总结，完成至少一条端到端路径。
- 质量门槛：能连贯讨论 3 轮；AI 不凭空引用原文；无正文授权时拒绝正文级问答。

### Milestone B：学习体验
- 登陆、用户偏好和会话持久化。
- 划词解释、表达收藏、复习卡片、学习回顾。
- 质量门槛：一次学习产生的表达第二天可以找到并完成复习。

### Milestone C：新闻发现与合规
- 实装来源策略和授权闸门；先上元信息/外链模式的 RSS。
- 为已确认授权的内容来源添加正文级适配器。
- 质量门槛：每一篇展示/传模型的内容可追踪许可决策和审查日期。

### Milestone D：迭代与扩展
- 小规模用户测试、纠错反馈优化、成本优化、移动端提升。
- 视反馈考虑语音、PWA、更多新闻源与个性化推荐。

## 2. 用户验证
最少 5 名目标用户参与定性可用性访谈，重点看：
1. 能否在不解释操作的情况下开始一篇文章的 AI 讨论？
2. 是否愿意回答 AI 的第三个问题？
3. 纠错频率是否打断表达？
4. 总结是否帮助记住一个真正能用的表达？
5. 一周后是否想再来使用？

量化指标仅用于实验判断，不冒充已达成：
- 激活：第一次闭环完成率；
- 参与：每次平均有效英文回答轮次；
- 留存：7 日再次完成闭环用户占比；
- 学习体验：用户评分、复习完成率；
- 成本质量：模型每次闭环成本、超时率、拒答准确率。

## 3. 风险登记
| 风险 | 级别 | 应对 |
|---|---|---|
| 新闻正文版权/模型使用权 | 高 | 权利闸门；先自写教学材料；审查条款 |
| AI 纠错不准确 | 高 | 纠错分类、少量反馈、用户可反馈 |
| 模型聊天成本失控 | 中 | 上下文裁剪、token 限额、成本监控 |
| 新闻过难/质量参差 | 中 | 学习等级适配、自写简讯/用户兴趣筛选 |
| 用户只读不聊 | 中 | 读后直接第一问、降低输入门槛 |
| 用户会话隐私 | 高 | 最小化、权限检查、删除/导出 |
| 来源失效与假新闻 | 中 | 来源追踪、事实声明边界、失效降级 |

## 4. 需要产品负责人确认
- 平台：Web 优先还是桌面优先？
- 首批受众：A2、B1 还是 B2？
- 新闻形态：只有外链 + 原创教学简讯，还是已有授权新闻 API？
- 初期登录：邮箱账号还是无需登录的单机 Demo？
- 预算：模型服务每月预算及是否部署在自有服务器？
- 公开程度：开源项目和是否允许其他人注册使用？

## 6. Definition of Done
每个功能必须同时满足：可用的前端交互、后端校验、错误处理、测试、权限检查（如适用）、合规验证（如适用）、README/文档更新。不能以“AI 能正常回答一次”代替功能完成。
